# PLAN 009 — ajustar categoria

Branch: `feature/009-ajustar-categoria`

Decisões registradas aqui (a SPEC deixou ao plano, ou o plano encontrou ao ler o código; escolhido o mais simples):

- **O e2e novo vai por último em `e2e/sync.spec.ts`, não em `e2e/expenses.spec.ts`.** Os arquivos e2e rodam em ordem alfabética com `workers: 1` sobre o mesmo banco (`playwright.config.ts`), e o primeiro teste de `sync.spec.ts` afirma "Nunca atualizado": um "Atualizar agora" disparado em `expenses.spec.ts` (que roda antes) o quebraria. Em `sync.spec.ts`, último arquivo e o único que já dispara o sync, o teste roda depois dessa afirmação e ainda devolve o banco ao estado automático no fim, como a SPEC (D8) pede. O conteúdo do teste é o da SPEC; só o arquivo muda.
- Com `DASH_TRANSACTIONS_PATH=tests/data/e2e_transactions.json` o sync nunca mais cria `sync-t-1`, então `expenses.spec.ts` deixa de aceitar "5 gastos" nas **duas** linhas onde aceitava (`:32` com `[45] gastos` e `:97` com a alternativa `R$ 389,90`); as duas passam a afirmar só "4 gastos".
- Mock: `fakeCategories` = `[{ key: 'Food', label: 'Alimentação' }, { key: 'Shopping', label: 'Compras' }, { key: 'Groceries', label: 'Supermercado' }, { key: 'Transport', label: 'Transporte' }]`; em `fakeExpenses`, `category_key` deriva do rótulo por esse mapa (`'Compras'` → `'Shopping'`, `'Alimentação'` → `'Food'`, `'Transporte'` → `'Transport'`, `null` → `null`) e `category_source: 'auto'` em todos. O item sem categoria é o `id: 43` (`description: null`, `amount_cents: -43000`): o botão dele se chama "Trocar categoria de Sem descrição".
- Enquanto "Voltar para a automática" salva, o front não conhece o rótulo automático (o `Expense` não o carrega), então `chosen` fica `null` e o selo continua mostrando o rótulo atual com "Salvando…" abaixo.
- Teste de `set_manual` que confere `group_id`: semeia com `narrowed(seed, [r for r in seed["rules"] if r["match_kind"] == "category"])` (só regras por categoria), para que nenhuma regra por descrição capture o recebedor e a resposta seja determinística: `Groceries` → grupo "Alimentação", `Healthcare` → grupo "Saúde" (as duas existem em `app/taxonomy/seed.json`).
- Teste de migração "base pré-existente": copia para uma pasta temporária os arquivos de `SQL_FOLDER` cujo nome ordena abaixo de `"019"`, aplica, insere conta e lançamento com `category = 'Groceries'`, copia `019_category_manual.sql` e aplica de novo.
- `_upsert` ganha `overrides: dict[str, str] | None = None`; para cada coluna (exceto a chave) a expressão de atualização é `overrides.get(column, f"excluded.{column}")`.
