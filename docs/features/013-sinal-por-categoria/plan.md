# PLAN 013 — sinal por categoria

Branch: `feature/013-sinal-por-categoria`

Decisões registradas aqui (a SPEC deixou ao plano, ou o plano encontrou ao ler o código; escolhido o mais simples):

- **O handler MSW de `by-category` ganha os campos novos na fase 1, com o backend**, para a fase 2 nascer com o contrato simulado igual ao real (modelo do plano 012). A fase 1 é só Python mais `src/testing/mocks/handlers.ts`; `pnpm typecheck` continua verde porque o handler devolve campos a mais num `HttpResponse.json` sem tipo.
- **Os dois testes de API que comparam a resposta inteira de `by-category` mudam de conteúdo, não de nome**: `test_an_empty_base_answers_no_groups` passa a esperar `{"groups": [], "total_cents": 0, "over_limit_count": 0, "signal_scope": "none"}` e `test_the_by_category_response_has_the_contract_fields` passa a esperar as chaves `{"groups", "total_cents", "over_limit_count", "signal_scope"}` no corpo e `{"category", "label", "count", "total_cents", "limit_cents", "signal"}` em cada grupo.
- **O rótulo da segunda linha do e2e é "Plano de saúde"**, não "Saúde": `Healthcare` tem esse rótulo em `app/taxonomy/seed.json`, e `e2e/expenses.spec.ts` já afirma `'Plano de saúde'` na linha 2 da tabela em `?month=2026-08`. A SPEC citou "Saúde" de memória; o teste segue o seed.
- **Os helpers de teste do front (`groupsOf`, `respondWith` em `category-totals.test.tsx`) passam a montar `CategoryGroup` completo** (`limit_cents: null`, `signal: null`) e `respondWith` aceita `over_limit_count` e `signal_scope` opcionais (padrão `0` e `'none'`), assim os dez testes existentes continuam com o mesmo nome e passam sem sinal.
- **Nenhum teste existente do front muda de nome.** Em `categories-list.test.tsx`, `saving a limit sends PUT, the row shows it and the categories query is invalidated` troca só a última asserção: de `not.toHaveBeenCalledWith(… ['expenses'])` para `toHaveBeenCalledWith(… ['expenses'])` dentro de `waitFor`.
- **O teste e2e novo entra em `e2e/expenses.spec.ts`** (o arquivo já está em `mode: 'serial'` e `playwright.config.ts` tem `workers: 1`), como um `test(` a mais, depois de `shows the totals by category and hides them when the filter has no spending`; ele deixa a base como encontrou apagando o limite no fim.
